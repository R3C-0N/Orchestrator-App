# Fixtures stream-json (claude 2.1.325, Windows 11)

Toutes les captures viennent d'un pilote Node de test (hors dépôt) qui lance `claude.exe`, écrit des messages JSON sur stdin et recopie stdout ligne à ligne. Les lignes préfixées `>>> ` sont les envois du pilote, `EXIT n` et `STDERR ` sont ajoutées par lui ; tout le reste est la sortie du CLI. Les arguments de lancement ne figurent pas dans les captures : les lignes de commande ci-dessous sont reprises du code du pilote et des commandes utilisées, sans reconstitution.

Dans toutes les captures : les champs `signature` des blocs `thinking` sont `REDACTED` ; le nom d'utilisateur Windows est remplacé par `<user>` (`C:\Users\<user>`), le dossier temporaire de session par `<session>` ; `account.email`, `account.organization` et `subscriptionType` sont `REDACTED`. Dans `t1`, le chemin de l'outil Read, qui arrivait en fragments `input_json_delta`, a été recollé dans le premier fragment (les suivants sont vides) pour pouvoir être neutralisé. Il n'y a pas de `t2` (numérotation d'origine conservée).

Commande de base commune : `claude.exe -p --input-format stream-json --output-format stream-json --verbose` + les options indiquées.

- `t1.jsonl` : `… --include-partial-messages --replay-user-messages --permission-mode manual` (pas de `--model` : modèle par défaut `claude-opus-5-5`). Deux tours dans un même processus ; montre `system/init` complet (rapporte `"permissionMode":"default"` pour `manual`), `hook_*`, deltas `text_delta` / `input_json_delta`, `tool_use` Read, `tool_result`, `rate_limit_event`, `result`.
- `t3.jsonl` : `… --forward-subagent-text --model haiku --permission-mode bypassPermissions` (pas de `--permission-prompt-tool`). Deux sous-agents en parallèle (`agent-bleu` en avant-plan, `agent-rouge` en arrière-plan) ; montre `task_started`, `task_progress`, `task_updated`, `task_notification`, `background_tasks_changed`, `parent_tool_use_id`.
- `t4.jsonl` : `… --model haiku --permission-mode default --permission-prompt-tool stdio`. Un `control_request` `can_use_tool` (Bash) puis un `AskUserQuestion`, avec nos `control_response` (lignes `>>> `).
- `t5.jsonl` : `… --model haiku --permission-mode default --permission-prompt-tool stdio --session-id 11111111-2222-4333-8444-555555555555`. `set_model` (haiku vers sonnet) et message `/orchestrateur ...` ; le test d'interruption y a échoué (le tour était déjà terminé), voir `t6`.
- `t6.jsonl` : `… --include-partial-messages --model haiku` (pas de `--permission-mode` : `init` rapporte `auto`, réglage utilisateur ; pas de `--permission-prompt-tool`). `interrupt` en plein tour avec deltas ; `result` `error_during_execution` / `aborted_streaming`, puis tour suivant normal dans la même session.
- `t7.jsonl` : `… --model haiku --resume 77cbd82d-c401-4ae6-a84e-8439cd39aecd` (session de `t4` ; pas de `--permission-mode` : `init` rapporte `auto`). Reprise : même `session_id`, contexte retrouvé.
- `t8.jsonl` : `… --include-partial-messages --forward-subagent-text --model haiku --permission-mode bypassPermissions --permission-prompt-tool stdio`, sans `--allow-dangerously-skip-permissions`. Un Bash qui écrit dans le dossier de travail part sans `can_use_tool`, et `AskUserQuestion` arrive seul en `control_request`. Elle tourne sur haiku : `--model` est facultatif, il n'est là que pour limiter le coût.
- `t9.jsonl` : `… --model haiku --permission-mode default --permission-prompt-tool stdio`, avec un pilote qui répond `deny` à tout `can_use_tool`. Un Bash refusé ; `tool_result` d'erreur côté Claude, `result.permission_denials` renseigné.
- `t10.jsonl` : `… --model haiku --permission-mode bypassPermissions --permission-prompt-tool stdio`, avec un pilote qui répond « ignorer » à `AskUserQuestion` (`answers:{}` + `annotations[question].unanswered:"skipped"`).
- `t11.jsonl` : `… --model haiku` (**pas de `--permission-mode`** : lancé dans le mode par défaut de la machine, `current_permission_mode` vaut `auto`, et non `bypassPermissions`). Requête de contrôle `initialize` envoyée juste après le lancement, sans message utilisateur ; réponse avec `commands`, `agents`, `models`, aucun `system/init`.
- `t12.jsonl` : `… --model haiku` (même lancement que `t11`, aucune requête ni message envoyé, stdin fermé après environ 12 s côté pilote ; la capture n'est pas horodatée). Ne contient que des `hook_*` : preuve qu'aucun `system/init` n'est émis avant le premier message.
